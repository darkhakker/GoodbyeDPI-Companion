HOW TO TEST
1. Install the extension from the review environment.
2. Open its popup. Read the one-time disclosure and click Allow/Continue. Before this action no request observation or automatic installer download takes place.
3. Run the downloaded Setup.exe and approve UAC. The project EXEs are currently unsigned; the underlying official GoodbyeDPI/WinDivert binaries and licenses are preserved. If your test environment blocks unsigned programs, consult the source or request clarification rather than bypassing its protection.
4. Close any separate GoodbyeDPI instance before enabling this companion's engine; the app reports conflicts rather than stopping other copies silently.
5. Open https://example.com. Open the popup: a card with the current hostname and an Add button appears at the top. Add it. The site remains in the list when the popup is reopened.
6. Enable the engine. A running-process status is not a claim that any particular site is unblocked. Functionality depends on the local ISP and network protocols.
7. Visit a selected site containing real external images/scripts/media. Open its Observed resources panel. Only actual HTTP/HTTPS request hostnames are learned, including delayed requests. There are no predefined CDN lists or hostname guessing. Existing parent coverage does not suppress exact observed names in the UI.
8. Remove the site, or disable discovery / exclude a third-party resource. Domains outside the effective list are not included in GoodbyeDPI's hostname-based modification rules. WinDivert still technically intercepts matching TCP packets to inspect/reinject them; this distinction is disclosed.
9. In Settings, revoke domain processing consent. Observation stops, ephemeral navigation hints are cleared, and the app requests engine shutdown. Re-consent is needed to resume.
10. To uninstall the Windows component, run Uninstall.cmd from its installed or extracted folder. This removes the service and native host registration but leaves local diagnostic files; manual cleanup locations are documented in the privacy policy.

DATA HANDLING
The extension processes active-tab URLs transiently to extract hostnames and stores last navigation hostname per open tab in storage.session, not a URL history. Selected domains, observed resource hostnames and settings are in storage.local. Only the resulting domains/profile/enable state go to the local Windows host. No domains, browsing records, telemetry, analytics or user identifiers are uploaded to the developer. The native helper uses the current Windows SID locally for pipe/ACL access control and can keep local technical logs. GitHub receives normal HTTPS download requests for the fixed installer, not selected-site data.

REMOTE CODE
